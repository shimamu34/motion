# Manus実装仕様：シーク完了後に動画フレームを更新する（H2の最小改善）

## 目的と優先順位
- 現在の `main/index.html` では、`seek()` が `video.currentTime` を設定した直後に `updateFrame()` を呼び、まだ移動先フレームが準備できていない可能性がある。
- 一方、`frameStep()` は `video.onseeked` で更新するが、再生中に `pause()` すると `onpause` 側の更新が先行する可能性がある。
- 教員の動画分析で、スライダーやコマ送り直後の画面更新がシーク完了より早く走らないようにする。

## 実装担当
- **Manusがコード実装の主担当。** ChatGPTは仕様・GitHubの差分とCI確認。PR作成後は既存Cue `developer` が新規PRイベントを受け取りレビューする想定。
- **現段階ではPRを作らない。** まずManusが下記の既存作業ブランチにだけコミットし、GitHubのコード確認後にChatGPTがPRを作成する。この順番ならCueは実コードをレビューできる。
- 作業ブランチ: `fix/motion-seek-after-seeked-2026-11-12`
- 変更対象: `index.html` および必要があれば `tests/motion-seek-phase2.test.js`。
- 以下の機能はそのまま保持: 動画再生/停止、速度7段階、左右反転、モデル失敗時の動画表示、既存コマ送り、ObjectURL解放、UIの日本語表示。

## 実装内容（小さな1件）
1. **スライダー操作 `seek()`:** `video.currentTime` 設定前に更新待ちの状態を管理し、シーク完了前には移動先フレームとして `updateFrame()` を新規起動しない。描画は原則 `seeked` 後。
2. **`frameStep()`:** 既存のコマ送り機能を維持し、再生中からコマ送りした場合でも `pause` イベントの画面更新がシーク完了前に走らないようにする。
3. **`onseeked`:** スライダー・コマ送りのどちらでも、移動後のフレーム表示を更新する。複数のイベントが来る場合の重複描画を可能な範囲で抑える。
4. **`onpause`:** 通常の一時停止では従来どおり画面を更新するが、シーク処理中は早すぎる画面更新を避ける。
5. プレーやシークができない状態での挙動を壊さない。フレーム番号の正確な保証、60fps対応、骨格の厳密な同一フレーム同期などは今回の対象外とし、未検証と報告する。

## 受入条件（必須）
- `node tests/motion-phase1.test.js` : 既存11項目の回帰テストをすべて通す。
- `node tests/motion-seek-phase2.test.js` : このブランチに追加済みのシーク用テストを通す。**このテストは未修正のコードでは失敗するよう意図した先行テスト**。
- テストの項目：停止中のスライダー操作、再生中からのスライダー操作、再生中からのコマ送り、短時間の連続シーク、モデル読み込み完了状態でもシーク前の描画が始まらないこと。
- テストが環境上で実行できない場合は成功と断定しない。
- 実ブラウザ・Chromebook・iPhone Safariの検証は別に必要。Nodeのフェイク動画イベントを実機検証と呼ばない。

## 制限
- `main` への直接書込み、PRの作成・マージ、公開・デプロイ、GitHubの設定・権限変更は禁止。
- Manusが実装する。ChatGPTは追加のManus APIタスクを作成しない。無料クレジットがなくなれば中断し、無断で課金や重複タスクを作らない。
- 生徒・学校関係の動画や個人情報、未公開資料、認証情報は使用しない。検証にはモックや架空の動画だけを使用する。
- Cue/Claudeなど他AIをManusから自動起動しない。

## Manusから必要な報告
- 実装ブランチの更新後の40桁HEAD SHA／変更したファイル／コミット
- 既存Phase1テストと新Phase2テストの結果
- 実機未検証と、特に非同期推論中のシークの残リスク
- 翌日再開メモ：完了内容／残課題／次の最初の一手／未実施テスト

この実装仕様はユーザーが承認した実際のアプリ改善作業を1件に限定するものであり、アプリ全体の完成を意味しない。
