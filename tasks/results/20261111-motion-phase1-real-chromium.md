## 最初の2回の失敗の扱い
1. CI run `42967280778` はテスト用動画生成ツール`ffmpeg`がGitHubランナーに存在せず、準備段階で失敗。ランナー内に必要なときだけ導入するよう修正。
2. CI run `42967435716` では、実動画は再生されるが**透明なCanvasだけのRGB値**を検査し黒画面と誤判定。透明Canvasの下に実動画を表示する設計は妥当なので、**ブラウザ合成後のスクリーンショットを検査する方式に変更**。
3. CI run `42967647587` で修正後テスト9件がPASS。過去の失敗を隠さず、テスト自体の誤りとアプリ不具合を区別して記録。

## 未検証（本レポートの合格に含めない）
- 実際のTensorFlow.js/MoveNetをCDNからダウンロードした場合の**姿勢推定・スティック表示・性能**。
- Chromebook実機とiPhone Safariの動画コーデック、パフォーマンス、再生速度（0.05倍等）。
- 学校ネットワークのフィルタ・プロキシ条件、通信先。
- 正確な1フレーム送り、シーク位置での動画と骨格の同一フレーム性、非同期処理の競合（H2/H3、第2段階）。
- 長時間使用や多くの動画切替に伴うメモリ使用量。
- Playwrightはheadless Chromeを操作した。人間が画面上で実際に操作した検証でもChromeOSそのものの検証でもない。

## 次に実施する実機確認（ユーザーの学校等のプライバシー保護前提）
- 1: Chromebookまたは手元のPCで開発ブランチのHTMLをローカルで開く。テスト用の無人動画を選び、再生/停止/速度変更/シーク/左右反転を確認。
